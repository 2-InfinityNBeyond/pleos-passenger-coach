# 요구서 v0.4: 동승자 실시간 조작 화면 (앱 이름: 눈치코치)

> **v0.4 변경(2026-11-15 낮, 사용자 요청)**: 출발 전에 오늘 갈 길을 미리 따라가 보는 **미리 가 보기(F20)** 를 주요 기능으로 추가. 사용자의 인터뷰에서 나온 요구(초보 운전자는 가까운 곳부터 연습 거리를 늘려 가며, 나가기 전에 그 길을 미리 보고 싶다)를 반영했다. 2절 목표에 두 번째 목표를 더했고, 경로 주변 길 모양을 받으려고 경로를 외부 서비스로 보내게 되어 9절 7번과 동의 화면 문구를 고쳤다(동의를 다시 받음).

> **v0.3 변경(2026-11-15 새벽, 사용자 요청)**: 앱 이름을 **눈치코치**로 확정. 글자를 줄이고 그림 위주로 바꾼 새 주행 화면(F16), 지도와 경로 선(F17), 안내 띠와 표지판(F18), 물어볼 것 버튼(F19)을 추가. 지도와 길을 그리기 위해 현재 위치와 목적지를 외부 서비스로 보내게 되어 9절 7번과 10절을 고쳤다. 가상 사용자 인터뷰(26세 면허 준비생) 답변을 반영했다.

> **v0.2 변경(2026-11-15, 사용자 요청)**: v0.1에서 "향후 계획"이던 학습 기록, 연습 상황 선택, 코치 모드, 운전자 동의, 동의 철회, 야간 화면을 이번 구현에 넣었다. 해설에 조작의 쓰임 한 줄("왜")을 붙여 2절 목표와 맞췄다. 이에 따라 6절, 7절, 8절, 9절, 10절, 12절을 고쳤다.

- 작성일: 2026-11-13 / 상태: **v0.1 확정** (사용자 확정 2026-11-13 밤). 시동 꺼짐은 표기하지 않고 신호가 끊기면 "차량 신호 없음"으로 표시 **[결정]**

## 1. 한 문장 문제
면허가 없는 동승자(예비 운전자)는, 가족 차에 타서 도로를 보는 동안, 운전자의 조작(핸들·깜빡이·브레이크)과 판단이 눈에 보이는 정보로 전달되지 않고 교재에는 실제 장면이 없기 때문에, 운전 조작을 장면과 연결해 배우지 못한다. 그 결과 **연수 비용**(참고: 한 학원의 정규 과정 858,000원, 사설 연수 요금은 [확인 필요])에 기대고 첫 운전에서 당황하게 된다.
- 지금의 대안: 학원, 시뮬레이터 앱(도로로), 연수 매칭 앱(운전결심, 운전선생), 유튜브

## 2. 목표 (1개)
면허 준비생이 가족 차에 동승하는 동안, **운전자의 조작(핸들 각도, 깜빡이, 브레이크, 기어)과 내비 안내를 한 화면에서 실시간으로 보고**, 그 조작이 왜 필요한지 짧은 해설로 이해한다.

두 번째 목표(v0.4): 초보 운전자와 면허 준비생이 **출발하기 전에 오늘 갈 길을 미리 따라가 보며**, 회전교차로나 막히는 구간처럼 미리 알아 둘 곳과 그곳의 요령을 파악한다.

## 3. 사용자
1순위 면허 준비생 / 2순위 면허 직후 초보 운전자 / 부가: 동승 코치(연수 강사가 초보 운전자 연수 중 함께 보는 보조 장비) **[결정]**

## 4. 바꿀 행동 (이 앱이 있기 전 → 후)
| | 앱 없음 | 앱 있음 |
|---|---|---|
| 동승자의 자세 | 운전자의 손과 발을 보려고 몸을 돌리거나 기울인다(사용자 추측, [확인 필요]) | **가만히 앉아 앞을 보며** 앱 화면을 본다 |
| 볼 수 있는 것 | 운전자 상체까지. 페달, 핸들 각도는 안 보임 | 핸들 각도, 방향지시등, 브레이크 켜짐, 기어가 화면에 표시 |
| 내비와 조작의 연결 | 내비 화면 따로, 운전자 따로 봐야 함 | **내비 안내(예: 좌회전)와 실제 조작(깜빡이 시점, 핸들 각도)을 한 화면에서 대조** [확인 필요: 내비 안내 데이터 실제 필드] |
| 학습 | 문제집의 글자 설명 | 실제 도로 장면 + 같은 시점의 조작 데이터 |

## 5. 화면 방식
- 전제 **[결정]**: **동승자 전용 디스플레이**에서 실시간 표시. 위치는 뒷좌석 → 조수석 → 태블릿으로 확장하며 기획서에는 "향후 계획"으로 명시(공지상 허용)
- **[확인됨]** 에뮬레이터에서 기어 D, 40km/h일 때 **센터 화면의 앱은 "주행 중에는 사용할 수 없습니다"로 차단**(DO 미선언), **DISPLAY2 창의 앱은 그대로 표시**(1회 확인). 실차 동작은 [확인 필요]
- 센터 화면(운전자 쪽)에는 주행 중 앱이 뜨지 않으며, 이 앱은 운전자 화면을 사용하지 않는다

## 7. 기능 범위
| # | 기능 | 설명 | 이번 구현 |
|---|---|---|---|
| F1 **핵심** | 실시간 조작 화면 | 핸들 각도(그림+숫자), 방향지시, 브레이크 켜짐, 기어, (가능하면) 내비 다음 안내 | 포함 |
| F2 | 이벤트 자동 감지 | **방향지시 켜짐 → 핸들 변화**(회전/차선 변경 패턴), 브레이크 켜짐/꺼짐, 기어 전환, **내비 안내 시점과 조작 시점의 시차** | 포함 |
| F3 | 코치 해설 | 규칙 기반 짧은 문장(예: "깜빡이를 켠 뒤 핸들을 왼쪽으로 돌렸어요") + **조작의 쓰임 한 줄**(예: "깜빡이는 주변 차와 보행자에게 갈 방향을 미리 알려요"). 평가가 아니라 쓰임만 말한다. 해설은 8초 뒤 흐려지고 30초 뒤 지워진다. 문구는 강사 검수 대상 **[확인 필요: 검수 전]** | 포함 |
| F4 | 안전·동의 | 첫 실행 동의와 면책, **운전자 동의 체크**(운전자가 직접 누름), **동의 철회**(설정, 철회하면 기록과 설정 삭제), 운전자 화면 비사용, 주행 중 입력 없음 | 포함 |
| F5 | 데모 모드 | 시나리오를 반복 재생(PT와 영상용), 제목 5번 탭 | 포함 |
| F6 | 학습 기록 | 해설 문장과 시각을 **이 기기 안에만** 저장(최근 300개), 기본 꺼짐, 보기와 모두 지우기. 데모는 기록하지 않음 | 포함(v0.2) |
| F7 | 연습 상황 선택 | 전체 / 회전 / 출발과 정차 중 하나를 고르면 그 상황의 해설만 표시. 조작 표시는 그대로 | 포함(v0.2) |
| F8 | 코치 모드 | 쓰임 한 줄을 숨기고 일어난 일만 표시(강사가 직접 말로 설명하는 상황). **[제안]** 요구서에 정의가 없어 가장 작은 형태로 만듦 | 포함(v0.2) |
| F9 | 야간 화면 | 차량의 야간 모드를 따라 어두운 바탕으로 바뀜(운전자 눈부심 줄이기) | 포함(v0.2) |
| F10 | 주차(후진) 해설 | 핸들을 돌린 양을 **반 바퀴 단위**로 알림(반 바퀴, 한 바퀴, 한 바퀴 반), 핸들 각도 옆에 바퀴 수 표시, "핸들을 왼쪽으로 한 바퀴 돌려 놓고 브레이크를 뗐어요"처럼 **순서**를 해설, 다시 풀기 시작하면 알림. 기어 R의 해설은 연습 상황 "주차"로 분류. **후방 카메라와 주차 센서는 Vehicle SDK에 API가 없어 쓰지 못함 [확인됨]**, 움직인 거리는 [확인 필요](주행 거리 신호는 있으나 짧은 거리가 잡히는지 미확인) | 포함(v0.2) |
| F11 | 알아 두기(상황별 팁) | 신호로 알 수 있는 7개 상황(출발 전, 좌회전 예정, 우회전 예정, 유턴 예정, 멈춰 있을 때, 후진과 주차, 주차한 뒤)에 도로교통법 규칙과 운전 요령을 두 줄 이하로 표시. 지시가 아니라 "이런 규칙이 있다"는 안내. 코치 모드에서는 숨김. **신호 대기인지, 끼어들기가 있었는지, 이 교차로가 비보호인지는 알 수 없음 [확인됨]**. 문구는 검수 전 **[확인 필요]** | 포함(v0.2) |
| F12 | 합성 후방 화면 | 기어 R일 때 핸들 그림 자리에 **시뮬레이션 후방 화면**을 표시. 가이드선(빨강, 노랑, 초록)은 핸들 각도로 계산한 예상 경로이고 핸들을 돌리면 같이 휜다. **실제 카메라 영상이 아니며 화면에 "시뮬레이션"이라고 표시**. 주차 칸과 차의 움직임은 데모에서만 그린다(실제 신호에서는 차의 위치와 속도를 모름 [확인됨]). 핸들 비율 15:1, 축 거리 2.9m, 차 폭 1.9m는 가정값 **[확인 필요]** | 포함(v0.2) |
| F13 | 방금 장면 되짚기 | 멈췄을 때(주차, 정차) 방금 한 조작 최근 3개를 순서대로 표시. 다시 움직이면 비움. 주행 중에는 앞을 보고 멈췄을 때 되짚는 사용 방식 | 포함(v0.2) |
| F14 | 추가 조작 신호 | 전조등, 상향등, 와이퍼, 운전석 안전벨트 경고, 문 열림을 읽어 상태 한 줄과 해설("전조등을 켰어요")로 표시. 연습 상황 "등화와 장치"로 분류. 못 받는 신호는 줄에서 빠짐(에뮬레이터는 안전벨트 경고 미지원 [확인됨]) | 포함(v0.2) |
| F15 | 신호등 잔여시간(참고용) | 공공데이터포털 "교차로 신호등 실시간 정보"(한국지역정보개발원)를 받아, 300m 안에 실시간 신호가 있는 교차로가 있으면 직진과 좌회전 신호의 색과 남은 초를 표시. **외부 데이터**이며 Pleos SDK가 아님. 차량 위치는 밖으로 보내지 않고 지역 전체 목록을 받아 기기 안에서 가까운 교차로를 고름. 제공 기관 고지에 따라 "참고용" 표시. 인증키가 없으면 기능이 꺼짐. **한계 [확인됨]**: 2026-11-15 기준 실시간 값이 오는 지역은 울산 399개 교차로뿐. 잔여시간 단위는 문서에 센티초로 적혀 있으나 실측은 밀리초. **[확인 필요]**: 방향 칸(북쪽 등)이 접근로 방위라는 가정, 호출 한도 | 포함(v0.2) |

## 8. 기대 결과
### 정상
- 운전자가 핸들을 돌리거나 깜빡이를 켜거나 브레이크를 밟거나 기어를 바꾸면, 동승자 화면의 해당 표시가 **바뀐다**. 갱신 지연 목표는 **1초 이내** [확인 필요: 측정 전]
- 내비 경로가 있으면 다음 안내(예: "좌회전")와 현재 조작이 함께 표시된다 [확인 필요]
- 조작 이벤트가 감지되면 해설 문장 하나가 표시된다(한 번에 한 문장, 시선 부담 최소)
### 빈 상태 (값이 없을 때는 "값 없음"이라고 쓰지 않고 **차량 상태를 표기**) **[결정]**
| 상황 | 표기 |
|---|---|
| 기어 P | "주차 중" |
| 기어 N | "중립" |
| 기어 D/R이지만 조작 변화가 없고 브레이크가 켜져 있음 | "정차 중" (판정 규칙은 spec에서 확정) |
| 시동 꺼짐 | **표기하지 않음 [결정]**: 공개 SDK에 신호가 없어 추정이 틀릴 수 있음. 모든 신호가 끊기면 **"차량 신호 없음"** 으로 표시 |
| 내비 경로 없음 | "내비 안내 없음" 표시, 나머지 조작 표시는 정상 |
### 실패
| 상황 | 동작 |
|---|---|
| 해당 신호를 차량이 지원하지 않음(`checkXxxCapabilities`가 NONE) | "이 차량은 ○○ 신호를 제공하지 않아요", 그 항목만 비활성, 나머지는 정상 |
| 신호가 끊김(구독 콜백 중단) | **"차량 신호 없음"** + 마지막 값을 흐리게 표시 + 마지막 수신 시각, 앱은 종료되지 않음 |
| SDK 초기화 실패 | 안내 문구와 다시 시도 버튼 |
| 시작 직후 연결 중 | "차량에 연결하는 중"(3초), 그 뒤에도 값이 없으면 "차량 신호 없음" |
| 값이 한동안 안 바뀜 | 끊김으로 보지 않는다. 4초마다 지금 값을 다시 물어 응답이 오면 정상 |
| 내비 정보를 못 받음(권한, 연결 실패) | "내비 정보를 받을 수 없어요"(경로 없음과 구분) |
| 동의하지 않음 | 시작하지 않고 설명 화면 유지 |
| 운전자 동의 체크 없음 | "동의하고 시작" 버튼 비활성 |
| 기어 미지원 | 안내 없음: SDK에 기어 지원 여부를 묻는 API가 없음 **[확인됨]** |

## 9. 하지 않을 것
1. **차량을 제어하지 않는다** (읽기 전용) **[결정]**
2. **운전자를 방해하지 않는다**: 운전자에게 경고, 지시, 알림을 하지 않고 센터 화면에 표시하지 않는다 **[결정]**
3. **운전 점수나 평가를 하지 않는다** **[결정]**
4. 주변 차량(끼어들기, 사각지대)을 **감지하지 않는다**: 공개 SDK에 없음 **[확인됨]**. ADAS SDK가 공개되면 향후 확장
5. 가속페달과 속도를 Vehicle SDK로 표시하지 않는다 **[확인됨]** (속도는 내비 값 확인 후 재검토)
6. 주행 중 사용자 입력과 터치를 **요구하지 않는다**(설정은 주행 전에 고르는 선택 사항)
7. **운전자의 조작 데이터를 외부로 전송하지 않는다.** v0.3부터 지도와 길을 그리기 위해 **현재 위치(길 모양 요청은 약 100m 단위로 뭉뚱그림)와 목적지, 그 사이 경로(v0.4, 약 100m 단위로 뭉뚱그림)는 외부 서비스로 보낸다**(동의 화면에 밝힘). 신호등 공공데이터는 받기만 한다. 저장은 사용자가 학습 기록을 켠 경우에만, 해설 문장과 시각만, 이 기기 안에만 한다(v0.2에서 "저장하지 않는다"를 이렇게 바꿈). 핸들 각도 같은 원본 값은 저장하지 않는다

## 12. 확인 필요 (남은 불확실성)
1. 구독 콜백의 **실제 지연**(1초 이내 가능한가)
2. NaviHelper **TBT/DrivingInfo의 실제 필드**, 에뮬레이터에서 경로를 설정해 값이 나오는가, 속도 포함 여부
3. **시동 꺼짐** 판정 방법(공개 신호 없음)
4. 브레이크 신호가 **켜짐/꺼짐 외에 정도를 주는가**(샘플에서는 boolean)
5. DISPLAY2에서 주행 중 표시되는 동작이 **실차 정책과 같은가**
6. 앱 카테고리 선언, DO(주행 최적화) 선언 정책
7. 에뮬레이터 안정성(이 PC에서 멀티 디스플레이 옵션을 켜면 반복 종료)
8. 사설 도로연수 요금(사업성 숫자)
9. 코치 해설 규칙과 쓰임 문구의 정확성(강사 검수 필요)
10. 핸들 각도 기준(조금 6도, 돌림 20도, 가운데 3도, 반 바퀴 180도, 후진에서 돌려 놓음 90도, 풀기 90도)과 내비 거리 기준(300m)은 실차 데이터 없이 정한 값
13. 알아 두기의 법령 인용(도로교통법 제49조, 제50조, 시행령 별표 2, 시행규칙 별표 2)은 초안. 현행 조문과 대조하는 검수 필요
11. 실기 확인(v0.3): 차량 서비스를 강제로 멈춰 **신호 끊김 표시와 다시 시도 후 재연결을 확인함**. 미지원 신호 안내와 안전벨트 경고는 에뮬레이터에서 상황을 만들지 못해 미확인
14. 센터 화면은 **기어 D에서 속도 0이어도 앱을 차단**(에뮬레이터 확인). 실제 신호의 주행 장면은 센터 화면에서 볼 수 없다
15. 에뮬레이터의 NaviHelper는 목적지 좌표를 0으로 준다. 실차에서 값이 오는지 [확인 필요]
16. 방향지시등을 켜면 Pleos 시스템이 후측방 카메라 창을 앱 위에 띄운다(앱이 막을 수 없음). 동승석 창에서도 그런지 [확인 필요]
17. 길 모양 공용 서버(Overpass)가 느리거나 실패할 때가 있음. 받은 자리는 기기에 저장해 다시 쓰지만, 출시하려면 조건에 맞는 지도 자료 서비스가 필요
12. 동승석 창이 주행 규제의 예외인지(문서에 없음). 예외가 아니면 주행 중에는 앱을 볼 수 없다
