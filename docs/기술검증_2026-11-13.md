# 기술 검증 로그 (2026-11-13 밤, 직접 실행해서 확인한 것만 기록)

## 환경
- AVD `Pleos_Connect_v2_1` (API 34, Cold boot, RAM 4GB) 부팅 확인. 에뮬레이터 37.2, WHPX 가속 사용
- 이미지: 42dot `pleos_car_emulator` 4,087,751,964바이트, SHA1 일치 확인
- 도구: JDK 17(Temurin 17.0.21), Go 1.27.4(SHA256 일치), Host Display Bridge 1.0.0(소스 읽고 실행, 로컬 루프백 전용)
- Pleos Maven: Vehicle SDK **2.0.3, 2.3.2만 존재**(시작하기 문서의 2.3.1은 없음). 인증 불필요
- Vehicle 샘플 앱(2.3.2로 수정)을 JDK 17로 빌드, 설치, 실행 성공. "SDK initialized, SDK 2.3.2, Vehicle Service 2.3.22" 표시

## 2026-11-14 우리 앱으로 직접 확인한 것 ✅ (앱: `pleos-passenger-coach`, 에뮬레이터 실행)
- **우리 앱이 Vehicle SDK 4개 신호를 실시간 구독**: 핸들 각도(`PERF_STEERING_ANGLE`), 브레이크(`BRAKE_PEDAL_STATUS`, Boolean), 방향지시(`TURN_SIGNAL_STATE`), 기어(`VENDOR_GEAR_SELECTION`). 초기값 읽기와 구독 콜백 모두 동작. 값이 안 바뀌어도 핸들 값은 약 3초마다 재전달됨
- **지연**: 가상 콘솔에서 값을 바꾼 뒤 앱 수신까지 대략 -24~212ms(기기와 호스트 시계 오차 ±100ms 포함) → **0.2초 이하**, 요구서의 "1초 이내" 충족(에뮬레이터 기준, 실차 미검증)
- **핸들 부호 [확인됨]**: 가상 콘솔 +60 → SDK -60. 가상 콘솔 소스가 `rotate(+각도deg)`로 그림(CSS 양수=시계 방향=오른쪽)이므로 **SDK 양수=왼쪽(반시계), 음수=오른쪽(시계)** 이 맞음. 화면 회전과 문구("왼쪽/오른쪽 N°")를 이 기준으로 처리
- **앱 기능 동작 확인(에뮬레이터, 실제 SDK 신호)**: 코치 해설이 실제 신호로 `기어 P→D`, `내비가 좌회전을 안내하고 N초 뒤 왼쪽 깜빡이를 켰어요`, `깜빡이를 켠 뒤 핸들을 왼쪽으로 돌렸어요`, `핸들이 다시 가운데로 돌아왔어요`, `깜빡이를 껐어요`, `브레이크를 밟았어요/뗐어요`를 순서대로 출력
- **단위 테스트**: 코치 규칙 11개 모두 통과(평가/점수 단어 금지 검사 포함)
- **동의 전에는 신호를 읽지 않음 [확인됨]**: 동의 화면에서 logcat에 SignalLab/NaviLab 기록이 없음. 동의 후에 연결 시작
- **데모 모드**: 제목을 5번 탭하면 켜지고 "시험 자료(데모)" 표시와 함께 S1 시나리오를 반복 재생(시스템 카메라 팝업 없이 녹화 가능)
- **NaviHelper SDK 3.0.5 동작 확인**: 경로가 있을 때 `onTBTInfo` → `count=11 first=TURN_LEFT dist=80.0 desc=기업지원허브 방면`, `ROUTE_STATE mode=ROUTE_GUIDING`. 경로가 없으면 `mode=SAFE_GUIDING`, TBT 0개. 현재 위치(위경도, 방향), 도로 제한속도(경로 없을 때 0) 이벤트도 수신
- **필요 권한**: Vehicle(`CAR_DRIVE`, `CAR_POWERTRAIN`, `CAR_LIGHTS`, `READ_CAR_STEERING`), 내비 읽기(`NAVI_ROUTE`). 경로 요청 `requestRoute`에는 `NAVI_ROUTE_SEARCH`가 필요해서 **debug 빌드 전용 매니페스트**에만 선언(release에는 읽기 권한만)
- **NaviHelper 데이터에는 속도가 없음**: `DrivingInfo`는 목적지/경유지의 소요시간, 거리, 충전 정보. 속도는 앱에서 얻을 수 없음(확정)
- **시스템 동작**: 방향지시등을 켜면 Pleos 시스템이 후측방 카메라 영상 팝업(왼쪽 위 x 버튼)을 센터 화면 위에 띄움. 앱이 만든 것이 아님
- **앱 수명 주기**: 내비 앱이 앞으로 오면 우리 앱이 중지됨(센터 화면은 앱 1개씩). 그래서 구독을 onStop이 아니라 onDestroy에서 해제하도록 변경

## 문서로 확인한 "동승자 창" 근거 (2026-11-14, Pleos Window Policy 문서)
- **Connect-W(와이드 화면)에서는 앱 라이브러리가 운전석 쪽과 동승석 쪽 양쪽에 나타나고, 동승석 쪽에서 실행한 앱은 동승석 창에서만 실행된다**고 적혀 있음(https://document.pleos.ai/en/docs/connect/guide/docs-design/getting-started/window). 동승자 전용 창이 플랫폼 정책에 있다는 공식 근거
- 아직 모르는 것: 동승석 창의 앱이 주행 규제에서 예외인지(문서에 없음), 그 창에서 읽을 수 있는 차량 데이터 범위
- Connect-S(표준)에서는 앱 창이 1~2개이며 이 앱은 센터 화면에서 주행 중 차단됨
- Pleos UI 디자인 가이드: 색(토큰 이름만, 값은 이미지), 버튼(크기 값은 이미지)은 텍스트로 값을 읽을 수 없음. Typography, Iconography, App Icon, Animation 페이지가 따로 있음(미확인)

## 확인된 것 ✅ (2026-11-13)
1. **Virtual Console**: `adb forward tcp:8088 tcp:8088` 후 `http://127.0.0.1:8088/` (웹 UI). 브라우저 하트비트(`POST /browser/session?client=..` 1초마다)가 있어야 활성. 이 하트비트를 스크립트로 대신 보내면 브라우저 없이 사용 가능
2. **Virtual Console은 HTTP로 조작 가능**(사람 없이 자동화 가능):
   - `PUT /vehicle/gear?gear=Park|Reverse|Neutral|Drive`
   - `PUT /vehicle/controls?speed=<km/h>&accelerator=<0-100>&brake=<0-100>&steering=<-540..540>`
   - `PUT /vehicle/turn-signal?mode=Off|BlinkLeft|BlinkRight|FlashLeft|FlashRight`
   - `PUT /vehicle/body`(도어, 창문, 와이퍼 등), `/vehicle/seat`(좌석 점유), `/vehicle/lights`(비상등 등)
   - `GET /vehicle/state`, `GET /vehicle/catalog`
3. **에뮬레이터 신호에는 속도(km/h)와 가속페달(%)이 있다**(이전 "없음" 판단은 가상 콘솔 문서 목록 기준이라 틀렸음). 조향각(-540~540), 브레이크(%)도 있음
4. **Driving view가 값을 반영**: Drive + 40km/h로 설정 → 화면에 "40 km/h", 기어 "D" 표시
5. **센터 화면 주행 차단 확인(핵심)**: 기어 D + 속도 40km/h일 때 DO를 선언하지 않은 샘플 앱 위에 **"주행 중에는 사용할 수 없습니다."** 표시(제가 캡처로 확인). P로 되돌리면 앱 사용 가능
6. **Vehicle SDK 샘플**: 19개 도메인(Door, Brake, Car info, Display, Driving mode, EV battery, Fuel, HVAC, Light, Odometer, Safety, Seat, Side mirror, Steering wheel, Tire, Toll, Turn signal, Window, Wiper)
   - **Brake / Brake Pedal Status**: "Supported", `getCurrentBrakePedalStatus` 호출 성공, 브레이크 60% 입력 시 `onComplete: true`
   - **Turn signal**: 1개 기능("Turn Signal") 존재
   - Steering wheel: 2개 기능, 확인된 것은 "Hvac Steering Wheel Heat"뿐(나머지 하나는 화면 이동 문제로 미확인)
7. **DISPLAY2 생성 성공**: Bridge로 `DISPLAY2`(displayId 2, "Emulator 2D Display", 1280x720, FLAG_SHOULD_SHOW_SYSTEM_DECORATIONS) 생성. `am start --display 2`로 샘플 앱이 **Display #2에서 실행됨**(dumpsys로 확인, focus 및 windows가 displayId=2)

## 운영 메모 (재현용)
- 에뮬레이터가 한 번 예기치 않게 종료됨(원인 미상, 로그에 오류 없음, 종료 코드 5). 재실행 필요
- DISPLAY2를 **별도 창으로** 보려면 AVD `config.ini`에 `hw.multi_display_window=yes`, `hw.hotplug_multi_display=yes` 필요(기본값은 no). 설정 후 재부팅
- 재시작 절차: 에뮬레이터 실행 → `adb forward tcp:8088 tcp:8088` → 하트비트 루프 → Bridge(`go run . --avd Pleos_Connect_v2_1`) 재시작 → `PUT /api/window-policy/display/create` → `am start --display 2 -n <앱>/.MainActivity`
- 에뮬레이터를 다시 켜면 가상 콘솔 값과 DISPLAY2는 초기화됨

## SDK 라이브러리 직접 확인 (Vehicle-2.3.2.aar, NaviHelper-3.0.5.aar, FusedLocation-1.1.3.aar를 풀어서 javap로 확인, 문서가 아닌 실물 기준)
### 공개된 SDK 아티팩트 (Pleos Maven 조회)
- Vehicle(2.0.3, 2.3.2), NaviHelper(2.0.2, 2.0.3, 3.0.5), FusedLocation(1.0.4, 1.1.3), TextToSpeech, SpeechToText. **Adas 아티팩트는 없음**
### Vehicle SDK 2.3.2의 API 클래스(전체)
Brake, CarInfo, Display, Door, DrivingMode, EvBattery, Fuel, **Gear**, HVAC, Light, Odometer, Safety, Seat, SideMirror, SteeringWheel, Tire, Toll, TurnSignal, Window, Wiper
| 필요한 신호 | 결과 | 근거 |
|---|---|---|
| 조향각 | **있음, 구독 가능** | `getCurrentSteeringWheelAngle`, `registerSteeringWheelAngle`, `checkSteeringWheelAngleCapabilities` |
| 브레이크 | **있음(밟힘 여부, 구독 가능)** | `getCurrentBrakePedalStatus`, `registerBrakePedalStatus`. 샘플에서 `onComplete: true`(boolean). 밟은 정도(%)는 아님 |
| 방향지시등 | **있음, 구독 가능** | `getCurrentTurnSignalState`, `registerTurnSignalState` |
| 기어 | **있음, 구독 가능** (샘플 앱 19개 도메인 목록에는 없지만 SDK에 Gear 클래스 존재) | `getCurrentGearSelectionState`, `registerGearSelection` |
| 현재 속도 | **Vehicle SDK에 없음(확정)** | Speed 클래스/메서드 없음. DrivingMode는 크루즈 목표속도만, Odometer는 거리. FusedLocation의 LocationData도 위경도, 고도, 방향, 신뢰도만(속도 없음). NaviHelper `onDrivingInfo`, `onCurrentRoadSpeedLimit`는 존재하나 필드 미확인 |
| 가속페달 | **없음(확정)** | Accelerator 클래스/메서드 없음 |
| 도어, 좌석 점유, 안전벨트 | 있음 | Door, Seat(`getCurrentSeatOccupancy`, `registerSeatOccupancy`, `registerSeatBeltBuckledState`) |
| 주행 거리 | 있음 | Odometer(`registerDistanceDriven` 등) |
| 시동(전원) 상태 | **공개 API에 없음** | PowerSystem류 클래스 없음. 에뮬레이터 콘솔에는 Power System이 있으나 SDK API 아님 |
### 주변 차량 경고(사각지대, 전방 충돌, 차선 이탈, 레이더, 끼어들기)
- **Vehicle SDK 2.3.2에 없음(확정)**: 전체 클래스 이름과 바이트코드 문자열을 검색(Collision, BlindSpot, LaneDeparture, CutIn, Radar, SurroundView 등) → 없음
- Safety 도메인에 있는 것: 오일/브레이크액/변속기오일/워셔액 경고, 에어백 전개/활성 여부, 안전벨트 미착용 경고, 전원 차단 경고, **텔테일(계기판 경고등 전체: Airbag, ABS, ESC, TPMS, SeatBelt, DoorOpen 등)**
- 에뮬레이터 안에 `ai.pleos.playground.service.adas` 서비스가 있으나 **공개 SDK 아티팩트가 없음**. 공모전 공지상 "문서에 공개되지 않은 SDK는 사용 불가"
- 결론: 차가 이미 가진 주변 차량 경고 데이터는 **현재 공개 SDK로 접근 불가**. ADAS SDK가 공개되면 향후 계획으로 기재
### NaviHelper SDK 3.0.5 (내비 연동)
- 메서드: `getTBTInfo()`, `getRouteStateInfo()`, `getCurrentLocationInfo()`, `getDestinationInfo()`, `requestRoute`, `addWaypoint`, `cancelRoute` 등
- 이벤트 리스너: `onTBTInfo`(회전 안내 목록), `onDrivingInfo`, `onCurrentRoadSpeedLimit`(도로 제한속도), `onCameraAlert`(카메라), `onCautionPointInfo`(주의 지점), `onRouteStarted/Ended`, `onDestinationArrived`, `onNavigationStatus` 등
- 의미: **"내비가 좌회전을 안내한 시점"과 "핸들, 깜빡이"를 한 화면에서 대조하는 아이디어는 SDK 면에서 가능성이 있음.** 단 TBT 데이터 필드(회전 종류, 거리)의 실제 내용은 미확인(에뮬레이터 실행 필요)

## 확인 못 한 것 ❓
- **DISPLAY2에서 주행 중 차단이 되는지**: dumpsys상 앱 UI는 Drive 40km/h에서도 살아 있었으나, 이 PC에서 adb로는 DISPLAY2 화면을 캡처하지 못함(SurfaceFlinger에 display 0만 보임). **사용자가 DISPLAY2 창을 눈으로 봐야 확정**
(위 SDK 라이브러리 확인으로 해소된 항목: 조향각 API 있음, 구독 API 있음, 기어 API 있음, 속도/가속페달 API 없음, 주변 차량 경고 API 없음)
- **실제 값 전달 지연**(구독 콜백이 얼마나 빨리 오는지): 에뮬레이터에서 우리 앱을 만들어 측정해야 함
- NaviHelper TBT/DrivingInfo의 **실제 필드와 에뮬레이터에서 값이 나오는지**(속도 포함 여부)
- **시동(전원) 상태를 앱이 알 수 있는 방법**: 공개 API에 없음. 대체: 기어 P/N, DrivingMode 상태 등
- **에뮬레이터 안정성**: DISPLAY2 사용 시 qemu가 반복 종료(아래 참고), 멀티 디스플레이 옵션을 켜면 DISPLAY2 없이도 종료됨 → 옵션 끄고 사용해야 함. 이 PC 기준 DISPLAY2는 불안정

## 설계에 미치는 영향
- 센터 화면 앱은 주행 중 차단됨이 실증 → "동승자 전용 디스플레이 전제" 설계가 필수
- 신호 읽기: 구독이 불확실하므로 **폴링 주기와 지연을 spec에 명시**하고 측정
- 시연: 가상 콘솔을 HTTP로 스크립트화해 **데모 시나리오(깜빡이 → 핸들 → 브레이크)를 자동 재생** 가능 → F5 데모 모드의 기술적 근거
- 로드맵의 Virtual Console 항목: 속도, 가속페달도 에뮬레이션 가능으로 수정
